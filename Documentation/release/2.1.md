# Asynchronous Execution

Catalyst now supports asynchronous execution, enabling visualization work to
overlap with GPU compute phases. When enabled, `catalyst_execute()` returns
immediately after deep-copying data to a bounded queue, while a background
worker thread processes the visualization pipeline. Both `impl_initialize` and
`impl_finalize` also run on the worker thread, ensuring consistent interpreter
state for Python-based implementations.

**No simulation code changes required.** Configure via environment variables:

```bash
export CATALYST_ASYNC_ENABLED=1
export CATALYST_ASYNC_QUEUE_DEPTH=2        # default: 2
export CATALYST_ASYNC_AFFINITY_MODE=auto   # auto, manual, none
export CATALYST_ASYNC_WORKER_CORES="1,2,3" # for manual mode
export CATALYST_ASYNC_VERBOSE=1            # enable debug output
```

Or via Conduit params at initialization:

```
catalyst/async/enabled = 1
catalyst/async/queue_depth = 2
catalyst/async/affinity/mode = "auto"
```

Key features:

- Transparent to adaptors and implementations — zero code changes required
- MPI-synchronized skip decisions prevent collective deadlocks when the queue is full
- Thread affinity support via hwloc, Linux `pthread`, or Windows `SetThreadAffinityMask`
- Configurable via environment variables, JSON config files, or Conduit params
- No new public API functions — ABI stable at version 2

Optional params-based control:

- Query async status: `catalyst_about()` returns `catalyst/async/enabled`
- Flush queue: pass `catalyst/async/flush = 1` in `catalyst_execute()` params

See `docs/async_execution.rst` for detailed documentation.

# GPU-Resident Data Support

When async execution is enabled, Catalyst automatically detects and copies
GPU-resident arrays before enqueueing them. Simulation adaptors can pass
device pointers directly via `set_external()` — no manual staging required.

GPU runtime detection uses `dlopen`/`dlsym` so there is no build-time
dependency on CUDA or HIP:

- **CUDA**: CUDA Driver API (`cuPointerGetAttribute`, `cuMemcpyDtoH`)
- **HIP/ROCm**: HIP runtime API (`hipPointerGetAttributes`, `hipMemcpy`)

CUDA and HIP/ROCm are both supported across all versions.

# Implementation Path Info

`catalyst_about()` now returns additional information about the loaded
implementation:

- `catalyst/version`: The libcatalyst runtime version
- `catalyst/implementation_path`: Full path to the loaded library
  (or `"(stub)"` for the built-in stub)
- `catalyst/implementation_source`: How the implementation was found
  (`"environment"`, `"params"`, `"default"`, or `"stub"`)
- `catalyst/implementation_abi_version`: The ABI version of the loaded
  implementation
